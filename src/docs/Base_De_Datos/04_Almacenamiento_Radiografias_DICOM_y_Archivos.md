# Gestión de Radiografías DICOM y Archivos BLOB

El expediente odontológico requiere visualización de estudios radiográficos (periapicales, aleta de mordida, panorámicas y tomografías cone-beam).

---

## 1. Esquema de Metadatos Radiológicos

```sql
CREATE TABLE ESTUDIOS_RADIOLOGICOS (
    ID NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    PACIENTE_ID NUMBER NOT NULL,
    HISTORIA_CLINICA_ID NUMBER,
    TIPO_ESTUDIO VARCHAR2(50) NOT NULL CHECK (TIPO_ESTUDIO IN ('PERIAPICAL', 'PANORAMICA', 'ALETA_MORDIDA', 'CEFALOMETRICA', 'CBCT_3D')),
    NUMERO_DIENTE_REFERENCIA NUMBER(2),
    NOMBRE_ARCHIVO VARCHAR2(255) NOT NULL,
    MIME_TYPE VARCHAR2(100) DEFAULT 'image/png' NOT NULL,
    TAMANO_BYTES NUMBER NOT NULL,
    CHECKSUM_SHA256 VARCHAR2(64) NOT NULL,
    METADATOS_DICOM JSON, -- Soporte nativo para JSON en Oracle 23ai
    ARCHIVO_BLOB BLOB,
    FECHA_TOMA TIMESTAMP WITH LOCAL TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL,
    CONSTRAINT FK_RAD_PACIENTE FOREIGN KEY (PACIENTE_ID) REFERENCES PACIENTES(ID)
)
LOB (ARCHIVO_BLOB) STORE AS SECUREFILE (
    COMPRESS HIGH
    DEDUPLICATE
    CACHE
);
```

---

## 2. Estrategia Híbrida: Base de Datos vs Object Storage

1. **Miniaturas y Radiografías < 5 MB:** Almacenadas como `SecureFiles BLOB` con compresión activa en Oracle para transaccionalidad inmediata con la historia clínica.
2. **Tomografías Masivas (> 20 MB):** El campo `ARCHIVO_BLOB` se deja nulo y se almacena la URL prefirmada de un bucket S3 / MinIO dentro de `METADATOS_DICOM`.
