# Estrategias de Indexación y Performance en Oracle

Para soportar miles de consultas concurrentes desde el Frontend y el Chatbot IA con tiempos de respuesta menores a 50 milisegundos, se han diseñado índices especializados y esquemas de particionamiento.

---

## 1. Índices B-Tree Compuestos Estratégicos

```sql
-- 1. Búsqueda rápida de citas por paciente y rango de fechas
CREATE INDEX IDX_CITAS_PACIENTE_FECHA 
ON CITAS (PACIENTE_ID, FECHA_INICIO, ESTADO_CITA);

-- 2. Búsqueda de disponibilidad del odontólogo
CREATE INDEX IDX_CITAS_ODONTO_DISP 
ON CITAS (ODONTOLOGO_ID, FECHA_INICIO, FECHA_FIN, ESTADO_CITA);

-- 3. Búsqueda de condición dental en odontograma
CREATE INDEX IDX_ODONTO_HC_DIENTE 
ON DETALLES_ODONTOGRAMA (HISTORIA_CLINICA_ID, NUMERO_DIENTE);

-- 4. Búsqueda de personas por número de documento (Unique B-Tree)
CREATE UNIQUE INDEX IDX_PERSONAS_DOC 
ON PERSONAS (NUMERO_DOCUMENTO);
```

---

## 2. Particionamiento de Tablas Masivas

La tabla `NOTIFICACIONES_WHATSAPP` y `AUDITORIA_EVENTOS` crecen de manera exponencial. Se implementa **Particionamiento por Rango de Fecha Mensual**:

```sql
CREATE TABLE AUDITORIA_EVENTOS (
    ID NUMBER GENERATED BY DEFAULT AS IDENTITY,
    TABLA_AFECTADA VARCHAR2(60) NOT NULL,
    REGISTRO_ID NUMBER NOT NULL,
    TIPO_OPERACION VARCHAR2(20) NOT NULL,
    VALOR_ANTERIOR CLOB,
    VALOR_NUEVO CLOB,
    USUARIO_EJECUTOR VARCHAR2(80),
    FECHA_EVENTO TIMESTAMP WITH LOCAL TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL
)
PARTITION BY RANGE (FECHA_EVENTO) (
    PARTITION P_2026_08 VALUES LESS THAN (TIMESTAMP '2026-09-01 00:00:00 -05:00'),
    PARTITION P_2026_09 VALUES LESS THAN (TIMESTAMP '2026-10-01 00:00:00 -05:00'),
    PARTITION P_2026_10 VALUES LESS THAN (TIMESTAMP '2026-11-01 00:00:00 -05:00'),
    PARTITION P_FUTURO VALUES LESS THAN (MAXVALUE)
);
```
